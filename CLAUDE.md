# Human Management — PPE Attendance System

## Overview
Flask web app for employee daily check-in and PPE (Personal Protective Equipment) compliance tracking across manufacturing production lines.

Part of the **4M Management** ecosystem — shares the same Supabase project as the OEE/4M dashboard.

## Tech Stack
- **Backend**: Python 3.11 / Flask 3 / SQLAlchemy 2
- **Database**: Supabase (PostgreSQL) in production · SQLite for local dev
- **Frontend**: Jinja2 templates + Bootstrap 5.3 + Chart.js 4
- **Deploy**: Render.com (auto-deploy from GitHub via `render.yaml`)

## Local Development
```bash
pip install -r requirements.txt
cp .env.example .env        # then set DATABASE_URL
python app.py               # runs on http://localhost:5000
```

Leave `DATABASE_URL` unset to use SQLite (default). The app seeds demo data automatically on first run.

## Production Deploy (Render + Supabase)
1. Push to `main` branch — Render auto-deploys
2. Set env vars in Render dashboard:
   - `DATABASE_URL` — from Supabase → Settings → Database → URI (Transaction pooler)
   - `SECRET_KEY` — auto-generated by `render.yaml`

## Database Schema
Schema is managed in Supabase. See `schema_supabase.sql` for the full DDL.

Key tables shared with the 4M project:
| Table | Description |
|-------|-------------|
| `employees` | UUID-based employees (extended with `position`, `line_id`) |
| `production_lines` | Manufacturing lines with capacity |
| `ppe_items` | PPE item catalogue |
| `ppe_requirements` | Required PPE per production line |
| `attendances` | Daily check-in records |
| `ppe_checks` | PPE compliance per attendance |

## Pages
| URL | Page |
|-----|------|
| `/` | Dashboard — KPI cards, line summary, weekly trend |
| `/checkin` | Employee check-in + PPE verification |
| `/employees` | Employee management (CRUD) |
| `/ppe-management` | Configure PPE requirements per line |
| `/report` | Attendance reports + CSV export |

## Key Architecture Notes
- `employees.id` is a **UUID** (matches Supabase 4M project schema)
- `Employee.employee_id` maps to DB column `employee_id_code`
- `Attendance.employee_uuid` is the FK to `employees.id`
- `postgres://` URLs are auto-converted to `postgresql://` for Render.com compatibility
- `db.create_all()` only runs on SQLite (schema managed by Supabase migrations in production)
